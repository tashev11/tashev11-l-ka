# Политика безопасности L‑KA

Безопасность пользователей важнее публичного обсуждения технической детали уязвимости.

## Как сообщить об уязвимости

Если вы обнаружили проблему, которая может повлиять на аккаунты, сообщения, авторизацию, данные пользователей, бизнес-кабинет или инфраструктуру L‑KA, **не публикуйте технические детали в открытом GitHub Issue**.

Используйте официальные контакты, опубликованные на:

**https://l-ka.ru**

В теме или начале сообщения укажите: **Security / Уязвимость L‑KA**.

## Что желательно приложить

- краткое описание проблемы;
- затронутую платформу: Web / Android / Windows / macOS / iPhone-PWA;
- адрес страницы или функцию, где проявляется проблема;
- воспроизводимые шаги;
- ожидаемое и фактическое поведение;
- оценку возможного влияния;
- безопасный proof of concept, если он необходим для воспроизведения.

## Чего делать не нужно

Пожалуйста:

- не получайте доступ к чужим аккаунтам или сообщениям;
- не изменяйте и не удаляйте чужие данные;
- не проводите действия, способные нарушить доступность сервиса;
- не публикуйте токены, cookies, ключи и персональные данные;
- не раскрывайте технические детали уязвимости публично до её рассмотрения.

## Обычные ошибки

Проблемы интерфейса, установки, уведомлений и другие ошибки, не создающие угрозу безопасности, можно отправлять через обычный GitHub Issue.

См. [SUPPORT.md](SUPPORT.md).
